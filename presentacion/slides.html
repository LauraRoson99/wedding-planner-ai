2 · Objetivos

Tres objetivos

Desarrollar una aplicación que organice todos los aspectos de una boda desde un único panel, con asistencias de IA que automaticen las decisiones más repetitivas.

1 · Gestión integral

Cubrir en una sola herramienta todo el ciclo: cuenta y bodas, invitados y confirmaciones, grupos y mesas, tareas y agenda, presupuesto y proveedores, y un panel de seguimiento.

Capa de aplicación: el servidor

Cada petición del cliente recorre siempre el mismo camino:

Rutas de API RESTLas «puertas» del servidor.
Ej.: /api/invitados
›
ControladorComprueba que los datos que llegan son correctos antes de tocar nada.

ServicioAplica las reglas del negocio y habla con la base de datos.
TecnologíaQué esPor qué la elegí
Node.jsPermite ejecutar JavaScript en el servidor.Mismo lenguaje en cliente y servidor: menos cambio de contexto al desarrollar sola.
ExpressEstructura mínima para crear las rutas de la API.Maduro y simple; alternativas como NestJS imponen mucha estructura innecesaria aquí.

Separar «comprobar» de «hacer» permite probar la lógica sin levantar un servidor.

3 · Diseño · Capa 3 de 3

Capa de persistencia: los datos

Mi código«Dame los invitados de esta boda»
›
PrismaTraduce esa orden a lenguaje de base de datos y comprueba que los campos existen.
›
PostgreSQLGuarda la información y garantiza que sea coherente.

Qué aporta Prisma

El modelo se declara una sola vez en un fichero. A partir de él genera automáticamente el código de acceso y las migraciones: cada cambio de la base de datos queda registrado y es repetible.

Por qué así

Si me equivoco en el nombre de un campo, falla al compilar, no delante del usuario. Y las garantías —que un asiento no se repita, que al borrar una boda no queden restos— las impone PostgreSQL, no mi código.

3 · Diseño · Modelo de datos

Todo cuelga de la boda

  • Cada dato sabe a qué boda pertenece: eso permite el aislamiento.
  • Un asiento, una persona: lo impide la propia base de datos.
  • Los acompañantes apuntan a su invitado principal.
  • Al borrar una boda no quedan restos.

3 · Diseño · Integraciones

Servicios externos, aislados

// Única función que habla con la IA (solo en el servidor)
await openai.chat.completions.create({
  model: "gpt-4o-mini",
  temperature: 0.4,        // baja: respuestas consistentes
  messages: [
    { role: "system", content: reglas },
    { role: "user",   content: contextoDeLaBoda },
  ],
  response_format: { type: "json_schema", … },
});

Qué se envía: fecha, número de invitados, nombres y grupos. Qué no: correos, teléfonos ni contraseñas.

Correo

Si hay servidor configurado, envía de verdad; si no, usa una cuenta de pruebas que devuelve un enlace de vista previa.

Por qué aisladas

Cada servicio externo vive en un único fichero. Cambiar de proveedor no obliga a tocar el resto, y un fallo suyo no tumba la aplicación.

3 · Diseño · Transversal

Seguridad, en todas las capas

Al iniciar sesión se entregan dos credenciales distintas:

Token de acceso

Dura minutos. Viaja en cada petición. Si alguien lo robara, caduca enseguida.

Token de refresco

Dura días y se guarda en la base de datos, así que se puede anular: eso es cerrar sesión de verdad.

MedidaQué consigue
Doble comprobación de dueñoAunque cambies el identificador en la dirección, no puedes ver la boda de otra persona.
Responder «no encontrado»Si respondiera «prohibido», estaría confirmando que esa boda existe. Diciendo «no encontrado» no revelo nada.
Contraseñas cifradasSe guardan transformadas y no se pueden recuperar, ni siquiera desde la base de datos.
Arranque seguroSi las claves del servidor no son seguras, el servidor no arranca. Mejor eso que arrancar mal.

3 · Diseño · Aportación central

La IA propone, la pareja decide

1 · Contexto«Boda el 12/06/2027, 64 invitados, 9 mesas, 18 tareas ya creadas»
›
2 · ModeloSe le exige la forma exacta: título, categoría, prioridad y fecha
›
3 · Validación¿Están todos los campos? ¿Son del tipo correcto? Si no, se descarta
›
4 · Propuesta«Reservar catering · Banquete · Alta · 8 meses antes»
›
5 · ConfirmaciónLa pareja desmarca lo que no quiere y solo entonces se guarda

Fiabilidad del formato

Se exige a la IA una respuesta con una forma cerrada y se comprueba antes de usarla. Si no encaja, no se utiliza.

Control del usuario

La IA nunca escribe en la base de datos. Devuelve borradores que se guardan solo si la pareja los confirma.

4 · Implementación

El contrato con la IA

Contrato = acuerdo cerrado sobre la forma exacta que debe tener la respuesta. Se impone y luego se verifica.

// 1) Se le exige al modelo que responda con esa forma exacta
response_format: { type: "json_schema", json_schema: { …, strict: true } }

// 2) Se comprueba la respuesta antes de dársela al usuario
const resultado = esquema.safeParse(respuesta);
if (!resultado.success) throw { status: 502, message: "Formato no esperado" };
  • Se verifica aunque el proveedor ya lo garantice: no delego mis datos en un servicio externo.
  • Si la IA falla o no está configurada, se avisa con un mensaje claro y el resto de la aplicación sigue funcionando con normalidad.

4 · Implementación

El caso difícil: distribuir las mesas

Los identificadores de mesas e invitados se generan en cada boda, así que no se pueden fijar por adelantado: el modelo de lenguaje podría inventarse referencias que no existen.

Propuesta del modeloAsigna cada invitado a una mesa y un asiento
›
Se depuraSe descartan mesas que no existen, asientos fuera de capacidad y repetidos
›
Propuesta limpiaSolo entonces se le enseña a la pareja
›
Se aplica enteraEn un solo bloque: o se coloca todo, o no se toca nada
Nunca se confía en la salida del modelo de lenguaje: se contrasta con lo que hay realmente en la base de datos.

6 · Conclusiones

Conclusiones

  • Se ha construido una aplicación funcional y autocontenida que cubre el ciclo completo de organización de una boda, sin capa comercial de por medio.
  • La aportación diferencial no es usar IA, sino cómo: un patrón de propuesta verificada y bajo control del usuario, aplicado a las decisiones organizativas.
  • Los ocho objetivos planteados se han alcanzado, respaldados por 18 pruebas automatizadas e integración continua.
  • Limitación reconocida: el cliente todavía no cuenta con pruebas automatizadas propias.
